# DeepSeek Team 0.12.0

## English

0.12.0 adds a unified package update flow and refreshes coordinator hooks from the
newly installed package.

- `deepseek-team update` upgrades the installation through its existing manager and
  then runs `deepseek-team hooks refresh` from the new package in a fresh process.
  It supports pip inside a virtual environment, pipx and uv, with
  `--manager auto|pip|pipx|uv`, `--runtime auto|codex|claude|both`,
  `--version VERSION` and `--json`. Ambiguous, editable or local-source
  installations and a conflicting explicit manager are refused before replacement
  with recovery guidance.
- `deepseek-team hooks refresh --runtime auto|codex|claude|both --notify --json`
  refreshes already configured hook definitions, is idempotent and preserves
  foreign settings, disabled native hooks, permissions, access, effort and
  project on/off choices. Auto mode finds package-owned records in existing
  configuration; it never creates a new integration or attaches a project.
- The refresh report is schema version 1 and contains `version`, `status`, `hooks`,
  `required_actions` and `requires_user_action`. Status is `completed`,
  `action_required` or `failed`. Explicit refresh and update return `0` on
  completion, `3` when work completed with outstanding user actions, and `78` on
  failure. JSON stdout remains one valid object while notices may also go to
  stderr.
- Required actions are surfaced for redirected, noninteractive and JSON runs, and
  through native hook context. A `--notify` refresh and every changed definition
  ask the user to start a new session and review DeepSeek Team in `/hooks`,
  approving native trust if prompted. The package never grants native trust.
- Automatic first-use refresh covers ordinary CLI and lifecycle use after direct
  package-manager upgrades. Help/version, explicit integration management, worker
  execution and credential-management commands are skipped, and managed worker
  sessions do not change coordinator host settings.

### Direct-manager limitation

A wheel has no standard post-install callback. Updating directly with pip, pipx or
uv therefore cannot print a DeepSeek Team-owned post-install notice, and direct
manager output alone cannot carry the required user actions. Existing
installations upgrade once through their current manager, which is also when the
`update` command first becomes available. Scripts and AI agents must then run the
new package's explicit fresh check before reporting completion, including in
automated or noninteractive work:

```bash
deepseek-team hooks refresh --runtime auto --notify --json
```

Relay every pending `required_actions` entry and state that user confirmation is
still pending.

### Upgrade

From an installation older than 0.12.0, upgrade through the manager you already
use:

```bash
pipx upgrade deepseek-team
# or: uv tool upgrade deepseek-team
# or, inside an activated venv: python -m pip install --upgrade deepseek-team

deepseek-team hooks refresh --runtime auto --notify --json
```

Later releases can use `deepseek-team update`. `setup` remains available when a
full setup pass is wanted.

## Русский

0.12.0 добавляет единый процесс обновления пакета и обновляет хуки координаторов
из только что установленной версии.

- `deepseek-team update` обновляет установку через её текущий менеджер, а затем
  запускает `deepseek-team hooks refresh` из нового пакета в отдельном процессе.
  Поддерживаются pip внутри виртуального окружения, pipx и uv; доступны
  `--manager auto|pip|pipx|uv`, `--runtime auto|codex|claude|both`,
  `--version VERSION` и `--json`. Неоднозначная установка, editable- или
  local-source-установка и конфликтующий явный менеджер отклоняются до замены
  пакета с подсказкой по восстановлению.
- `deepseek-team hooks refresh --runtime auto|codex|claude|both --notify --json`
  обновляет уже настроенные определения хуков, идемпотентен и сохраняет
  посторонние настройки, отключённые нативные хуки, разрешения, доступ, effort и
  выбор включения/отключения проекта. Режим auto находит принадлежащие пакету
  записи в существующей конфигурации; он никогда не создаёт новую интеграцию и не
  подключает проект.
- Отчёт refresh имеет schema version 1 и содержит `version`, `status`, `hooks`,
  `required_actions` и `requires_user_action`. Статус — `completed`,
  `action_required` или `failed`. Явный refresh и update возвращают `0` при
  завершении, `3` — когда работа завершена, но остаются действия пользователя, и
  `78` — при ошибке. JSON в stdout остаётся одним валидным объектом, а
  уведомления могут дополнительно выводиться в stderr.
- Необходимые действия показываются при перенаправленных потоках,
  неинтерактивном режиме и JSON, а также через контекст нативных хуков. Refresh с
  `--notify` и каждое изменённое определение требуют начать новую сессию и
  проверить DeepSeek Team в `/hooks`, подтвердив нативное доверие, если будет
  предложено. Пакет никогда не подтверждает нативное доверие сам.
- Автоматический refresh при первом использовании охватывает обычные CLI-команды
  и жизненный цикл после прямого обновления пакета менеджером. Help/version,
  явное управление интеграцией, запуск воркеров и команды управления
  учётными данными пропускаются, а управляемые сессии воркеров не меняют
  настройки хоста координатора.

### Ограничение прямого менеджера

Wheel не имеет стандартного post-install callback. Поэтому прямое обновление
через pip, pipx или uv не может показать уведомление, принадлежащее DeepSeek Team,
и вывод менеджера сам по себе не передаёт необходимые действия пользователя.
Существующая установка обновляется один раз через текущий менеджер — тогда же
впервые становится доступна команда `update`. После этого скрипты и AI-агенты
обязаны запустить явную свежую проверку из нового пакета до отчёта о завершении,
в том числе в автоматическом или неинтерактивном режиме:

```bash
deepseek-team hooks refresh --runtime auto --notify --json
```

Передайте каждую ожидающую запись `required_actions` и укажите, что подтверждение
пользователя всё ещё ожидается.

### Обновление

Для установки старше 0.12.0 обновитесь через уже используемый менеджер:

```bash
pipx upgrade deepseek-team
# либо: uv tool upgrade deepseek-team
# либо внутри активированного venv: python -m pip install --upgrade deepseek-team

deepseek-team hooks refresh --runtime auto --notify --json
```

В последующих выпусках можно использовать `deepseek-team update`. Команда `setup`
по-прежнему доступна, если нужна полная настройка.
