# DeepSeek Team 0.8.3

Сгенерированные инструкции координатора теперь требуют планировать и маршрутизировать каждую
делегированную подзадачу, включая небольшие задачи на чтение истории, поиск и ревью, прежде чем
назначать другого агента. В режиме Auto результат регистрируется как `executor: "auto"`, а решение
о воркере означает DeepSeek. Обычные короткие ответы координатора не требуют фиктивного воркера,
ожидание и управляющие вызовы не создают работу, а новая работа для уже запущенного агента тоже
требует маршрутизации.

Собственные субагенты координатора теперь допускаются только как явное исключение:

- обычный параллелизм, изолированный контекст или удобство сами по себе не являются достаточной причиной;
- для нативной задачи нужны конкретный `delegation_reason` и `native_exception` — либо
  `{"code": "explicit_user_request", "evidence": "specific user request"}`, либо
  `{"code": "native_capability", "capability": "...tool unavailable to a DeepSeek worker", "evidence": "why it is required"}`;
- это свидетельство подтверждает координатор; оно не является механически доказанным источником от пользователя;
- в нативном запросе или сообщении должен быть `[deepseek-team:TASK_ID:DELIVERABLE_ID]`, привязывающий
  зарегистрированную область нативного агента, а его принятый или отменённый результат фиксируется как у любой задачи.

Родительский хук `PreToolUse` проверяет привязку перед запуском нативного агента и передачей
новой работы, в том числе в структурированных текстовых сообщениях. Он отклоняет отсутствующие,
чужие и неоднозначные маркеры, области работы DeepSeek-воркера, изменённые обоснования,
завершённые задачи и запись после отзыва доступа. Записи о запуске сохраняются при изменении
плана и требуют результата. Пути в свободном формате patch также проверяются по плану.

Архитектура, безопасность, интеграция, итоговая проверка, секреты/подпись и публикация остаются
только за координатором. В инструкциях о хуках теперь честно указано, что родительский шлюз запуска и
сообщений покрывает только те события, которые среда действительно передаёт, а не любую возможную
запись; покрытие Codex и Claude проверяется отдельно, и универсальное покрытие хуками не заявляется.
Там, где среда не может перехватить действие, действуют эти инструкции. Обязательная песочница ОС для
воркеров не меняется.

Локальные тесты с имитацией провайдера подтвердили блокировку нативного запуска в настоящих
Codex 0.153.2 и Claude Code 2.1.278. Отдельная платная диагностика DeepSeek прошла с включённой
песочницей ОС; основные настройки и авторизация координатора сохранились.

После обновления выполните `deepseek-team hooks install --runtime codex` (либо `claude` / `both`),
затем `deepseek-team init --coordinator codex .` (либо `claude` / `both`) в
подключённых проектах, чтобы обновить генерируемые инструкции. Пользовательский текст и сохранённые
настройки сохраняются.
