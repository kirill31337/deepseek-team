# DeepSeek Team 0.9.0

## English

0.9.0 makes workspace lifecycle and disk ownership explicit without changing the
worker sandbox, model, access profile or default concurrency.

- One logical job (`job_id`) keeps one stable workspace through preparation,
  process/check/API failures, review gaps without a PID, `needs-rework`, explicit
  resume and linked corrections. Every run has its own `attempt_id`, and
  implementation still never retries automatically.
- A successful process only means **awaiting review**. The coordinator integrates
  and verifies before final acceptance. Final acceptance, rejection, cancellation
  or abandonment closes the lease and removes the checkout, `.git`,
  `.deepseek-tools` and owned temporary environments; compact job, attempt, check,
  exit and `work_inode` history, the final binary and untracked `changes.patch`,
  diagnostics, provenance and lessons remain.
- Lifecycle control is available through `coordination use ... --final`,
  `coordination finalize ... [--cancel]`, and the `workspace finalize`, `cancel`,
  `recover`, `resume`, `list` and `history` commands. `recover` and `resume` repair
  ownership only and never start a model. A failed attempt resumes explicitly in
  the same inode with `worker --workspace ID --resume-after-failure`.
- `deepseek-team gc --dry-run` is the default and reports safe keeps/deletes with
  allocated bytes and inodes; `gc --apply` executes only reviewed safe deletions.
  Creation, preparation, start, import, review, verification, live leases and locks
  are protected. Unsafe or uncertain data is reported and kept, never removed by
  mtime alone.
- Saved tool recipes now rely on a finite immutable content cache independent of
  execution trees. Active workspaces still materialize tools independently, mutable
  files are never hardlinked, and stale cache entries invalidate a recipe with
  actionable guidance. Byte/inode reservations honor configured storage and
  `TMPDIR`, with no hardcoded `/mnt/data` default.
- After upgrading, run `setup` for each coordinator and `init` only to attach or
  deliberately repair project blocks. Setup/init use the same provider-free
  collector on known owned roots and preserve user guides and delegation settings.

The mandatory Linux OS sandbox, `deepseek-flash`, Auto and full-access policy
behavior, and the default `max_workers=8` are unchanged.

## Русский

В 0.9.0 явно описаны жизненный цикл рабочих копий и владение дисковым
пространством. Песочница, модель, профиль доступа и число параллельных воркеров по
умолчанию не меняются.

- Одно логическое задание (`job_id`) сохраняет одну стабильную рабочую копию во
  время подготовки, сбоев процесса, проверок и API, пауз на ревью без PID,
  `needs-rework`, явного возобновления и связанных доработок. У каждого запуска
  свой `attempt_id`; автоматического повтора реализации нет.
- Успешный процесс означает только **ожидание ревью**. Координатор интегрирует и
  проверяет результат до финальной приёмки. Приёмка, отклонение, отмена или отказ
  закрывают аренду и удаляют рабочую копию, `.git`, `.deepseek-tools` и
  принадлежащие заданию временные среды; компактная история задания, попыток,
  проверок, кодов выхода и `work_inode`, финальный бинарный и неотслеживаемый
  `changes.patch`, диагностика, происхождение и уроки сохраняются.
- Управление доступно через `coordination use ... --final`,
  `coordination finalize ... [--cancel]` и команды `workspace finalize`, `cancel`,
  `recover`, `resume`, `list`, `history`. `recover` и `resume` восстанавливают
  только владение и не запускают модель. Неудачная попытка продолжается явно в том
  же inode командой `worker --workspace ID --resume-after-failure`.
- `deepseek-team gc --dry-run` используется по умолчанию и показывает безопасные
  решения сохранить или удалить вместе с выделенными байтами и inode;
  `gc --apply` выполняет только проверенные безопасные удаления. Создание,
  подготовка, запуск, импорт, ревью, проверка, живые аренды и блокировки
  защищены. Небезопасные или неоднозначные данные описываются в отчёте и
  сохраняются, а не удаляются по одному mtime.
- Сохранённые рецепты инструментов используют конечный неизменяемый кэш
  содержимого независимо от деревьев выполнения. Активные копии по-прежнему
  независимо материализуют инструменты, изменяемые файлы никогда не связываются
  жёсткими ссылками, а устаревшая запись кэша делает рецепт недействительным с
  конкретной подсказкой. Резервирование байтов и inode учитывает настроенное
  хранилище и `TMPDIR`; жёстко заданного `/mnt/data` по умолчанию нет.
- После обновления выполните `setup` для каждого координатора, а `init` — только
  для подключения проекта или намеренного восстановления блоков. Setup/init
  запускают тот же сборщик без обращения к провайдеру для известных
  принадлежащих пакету корней и сохраняют пользовательские руководства и
  настройки делегирования.

Обязательная песочница Linux, `deepseek-flash`, поведение политик Auto и полного
доступа, а также `max_workers=8` по умолчанию не меняются.
