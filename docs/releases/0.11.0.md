# DeepSeek Team 0.11.0

## English

This release improves retained-job recovery, build preparation, managed checks and coordination diagnostics.

- Git index attestation permits stat-cache refreshes and verifies modes, paths, object IDs, flags and extensions. Result capture rebuilds a private trusted index from the recorded baseline. Supported index formats are v2/v3 with SHA-1/SHA-256 parsing in compatible repositories.
- `workspace cancel --discard-result --reason TEXT` and `coordination finalize --cancel --discard-result --evidence TEXT` provide explicit cancellation when capture fails in a supported, verified branch. They require current authorization to lose that copy's result. Unknown process outcomes and malformed capture responses preserve the copy, including oversized output. Ownership, mount, inode and live-process checks govern cleanup.
- Discarded results use schema 2 with `capture.status="discarded"` and `patch=null`. Historical patches retain their bytes and provenance. Durable requests, terminal lease state and cleanup intent support recovery after interrupted publication or deletion. Linked assignments close consistently and retain earlier quality assessments.
- Repeatable `workspace prepare --cache-dir REL_DIR` declares mutable build caches and saves them in recipe v2. Preparation recognizes future parents of staged files and directories. Cache contents participate in verification fingerprints. Removing a declaration preserves foreign exclude bytes, line endings, file modes and duplicate rules.
- `worker --check-timeout SECONDS` defaults to **1800 seconds, or 30 minutes, for new jobs**. Baseline and post checks share this limit, bounded by the remaining total job deadline. Resume inherits the last started execution attempt. Historical attempts without the field retain 120 seconds. Evidence records both configured and effective limits. Baseline runs before the provider credential is read and owns a durable attempt before the command begins.
- `coordination cancel --task TASK_ID --assignment ASSIGNMENT_ID --evidence TEXT` cancels untouched planned assignments. Launch reservations, process identity, queue/slot bindings and an allocation fence serialize cancellation with launch. Terminal history records cancellation before start.
- Plan validation reports changed logical fields and aggregates independent structural errors. Settings I/O failures produce controlled errors. Help exposes coordination commands and explains task-ID provenance. Python CI coverage includes 3.14.

### Compatibility

Recipe readers accept versions 1 and 2. Result readers accept schemas 1 and 2 and reject unknown formats. Result schema 2 requires a compatible reader from 0.11.0 onward.

An interruption between Git exclude publication and metadata persistence can leave a retained copy requiring inspection and explicit result discard. Recovery preserves its baseline and recorded history.

## Русский

Релиз улучшает восстановление сохранённых работ, подготовку сборок, управляемые проверки и диагностику координации.

- Аттестация Git index допускает обновление stat-кэша и проверяет mode, пути, object IDs, flags и extensions. Capture строит приватный доверенный index из записанной baseline. Поддерживаются форматы index v2/v3 с разбором SHA-1/SHA-256 в совместимых репозиториях.
- `workspace cancel --discard-result --reason TEXT` и `coordination finalize --cancel --discard-result --evidence TEXT` дают явный путь отмены при подтверждённом поддерживаемом отказе capture. Требуется действующее разрешение потерять результат конкретной копии. Неизвестный исход процесса и повреждённый ответ capture сохраняют копию, в том числе при слишком большом выводе. Очистка проверяет owner, mounts, inode и живые процессы.
- Потерянный результат записывается в schema 2 с `capture.status="discarded"` и `patch=null`. Исторические патчи сохраняют байты и происхождение. Durable request, терминальное состояние lease и cleanup intent позволяют продолжить прерванную публикацию или очистку. Связанные назначения завершаются согласованно с сохранением прежних оценок качества.
- Повторяемый `workspace prepare --cache-dir REL_DIR` объявляет изменяемые кэши сборки и сохраняет их в recipe v2. Подготовка распознаёт будущих родителей staged-файлов и каталогов. Содержимое кэша участвует в отпечатках проверок. Снятие декларации сохраняет чужие байты exclude, окончания строк, режим файла и дубликаты правил.
- `worker --check-timeout SECONDS` получает **1800 секунд, или 30 минут, для новой работы**. Один лимит действует на baseline/post checks и ограничивается остатком общего срока. Resume наследует последнюю начатую execution attempt. Для старой попытки без поля сохраняются 120 секунд. Evidence содержит настроенный и фактически применённый пределы. Baseline выполняется до чтения ключа провайдера и получает durable attempt до начала команды.
- `coordination cancel --task TASK_ID --assignment ASSIGNMENT_ID --evidence TEXT` отменяет неначатое planned-назначение. Reservation, идентичность процесса, привязка queue/slot и allocation fence сериализуют отмену с запуском. История фиксирует отмену до старта.
- Проверка плана называет изменённые логические поля и собирает независимые структурные ошибки. Ошибки чтения настроек обрабатываются контролируемо. Справка показывает coordination-команды и объясняет происхождение task ID. CI включает Python 3.14.

### Совместимость

Читаются recipe версий 1 и 2 и result schemas 1 и 2. Неизвестные форматы отклоняются. Result schema 2 требует совместимого reader из версии 0.11.0 или новее.

Прерывание между публикацией Git exclude и сохранением metadata может оставить копию, требующую осмотра и явного отказа от результата. Восстановление сохраняет baseline и записанную историю.
