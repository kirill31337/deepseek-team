# DeepSeek Team 0.10.0

## English

0.10.0 introduces the versioned overhead contract v1 and reduces repeated
coordination work. It does not change the mandatory Linux OS sandbox or retry
implementation automatically.

- Overhead contract v1 ships with the package and is delivered by fresh
  `setup`/`init` and by full or linked instruction-block refreshes after an
  upgrade or on the next lifecycle event, including `SessionStart` and
  `UserPromptSubmit` hook delivery. It preserves the
  human-maintained `docs/agents/delegation.md`, bytes and modes outside the
  managed block, line endings, saved on/off/access/effort policy and
  configuration. See the [English overhead
  contract](https://github.com/kirill31337/deepseek-team/blob/main/docs/OVERHEAD_CONTRACT.md)
  and [Russian guide](https://github.com/kirill31337/deepseek-team/blob/main/docs/OVERHEAD_CONTRACT.ru.md).
- Re-registering an identical normalized logical plan is a durable no-op: it
  preserves deliverable ids, routing decisions, phase, current outcomes and
  timestamps. Changed scope, requirements or dependencies require a replan.
  Semantic package boundaries, blocking or event-based waiting for agents, and
  reviewing the actual diff without repeating the worker's research remain agent
  recommendations, not universal enforcement claims.
- Deterministic project-check reuse is opt-in. `checks_reusable` is a strict
  boolean defaulting to `false`; only explicit `true` attests that every command
  is a deterministic, project-local check. Reuse is available through
  `workspace verify --reuse-checks`; `workspace verify --force` and managed
  worker `--force-checks` always execute. A reused result requires confirmed
  unchanged represented project inputs and environment plus valid prior
  successful evidence. Changed, unknown, failed, truncated or unsafe evidence,
  and every explicit force, require execution. Readiness, security and
  containment probes are always fresh, and coordinator acceptance is never
  inferred from a reused worker check alone.
- Known pre-provider environment failures are remembered in a bounded private
  record, so identical environment preparation and workspace-allocation
  attempts are blocked before provider access while the relevant conditions
  remain confirmed unchanged. Changed
  conditions or `--recheck-environment` permit a fresh diagnostic. This memory
  never bypasses sandbox, access, admission or recovery gates, and does not cover
  provider, authentication or ordinary project-test failures.
- Worker-slot waits use kernel notifications with a conservative fallback,
  preserving FIFO order, deadlines and cancellation. Process exit wakes waiters;
  avoiding frequent coordinator polling remains an instruction to the agent.
- An explicitly planned correction of a reviewed successful `needs-rework`
  result can declare `correction_of {task_id, assignment_id}`. Before
  allocation, the runner resolves the original still-open workspace and job,
  reuses its stable copy and prepared tools, and starts a new attempt. The
  coordinator does not need to remember or pass `--workspace`; a conflicting
  explicit value fails. Invalid, ambiguous, stale, foreign, finalized or unsafe
  links fail before allocation. Failed attempts still require an explicit
  `--resume-after-failure`.
- Post-compaction `SessionStart` and `UserPromptSubmit` summaries restore
  workspace, job, attempt and correction lineage from the private ledger,
  independent of model recall. The omitted-link overlap guard is task-local;
  semantic cross-task corrections require an explicit link. Finalization follows
  the accepted correction chain across tasks. Hook delivery covers recognized
  events the runtime delivers, not every possible write.
- Current planned state uses schema 2. No migration for older planned-state
  formats is supplied; those formats are diagnosed but are not migrated or
  treated as compatible. This is separate from preserving the human guide and
  saved user policy/configuration.

Upgrade through the same package manager, then run `setup` for each coordinator
runtime you installed:

```bash
pipx upgrade deepseek-team
deepseek-team setup --runtime codex --no-key   # or claude / both
deepseek-team doctor --runtime codex --offline
```

Installing the package alone does not attach a project or grant native hook
trust. Live lifecycle delivery requires enabled delegation and delivered hook
events.

### Verification

The exact candidate was checked with
`PYTHONPATH=src python3 -m unittest discover -s tests -v`: 1776 tests passed
with 5 expected skips for three missing-Claude-CLI cases, optional GC stress, and
the absent nested-mount fixture. The actual installed final wheel passed 24
functional tests without skips. An additional real sandbox capture and completion
of both tasks in a linked-correction scenario also passed. Six installation scenarios passed:
full and linked variants across fresh install, 0.9.0-to-0.10.0 upgrade plus
setup, and upgrade plus `SessionStart` hook; the human guide, outside bytes and
modes, and saved policy/configuration were preserved, and repeating unchanged
setup was a no-op. All 63 package files matched the final tested wheel
byte-for-byte.

These results are evidence for this candidate, not guarantees for every machine.
Native Claude execution was not claimed, and hook enforcement is not universal.

## Русский

В 0.10.0 появился версионируемый контракт накладных расходов v1 и сокращена
повторная работа координации. Обязательная песочница Linux и отсутствие
автоматических повторов реализации не меняются.

- Контракт v1 поставляется с пакетом и доставляется при чистых `setup`/`init`, а
  также при обновлении полных или компактных блоков инструкций после апгрейда
  или на следующем событии жизненного цикла, включая lifecycle hooks
  `SessionStart` и `UserPromptSubmit`. Сохраняются
  поддерживаемый вручную `docs/agents/delegation.md`, байты и режимы вне
  управляемого блока, переводы строк, сохранённые политика on/off/access/effort
  и конфигурация. См. [контракт на английском](https://github.com/kirill31337/deepseek-team/blob/main/docs/OVERHEAD_CONTRACT.md)
  и [руководство на русском](https://github.com/kirill31337/deepseek-team/blob/main/docs/OVERHEAD_CONTRACT.ru.md).
- Повторная регистрация идентичного нормализованного логического плана — это
  устойчивый no-op: сохраняются id deliverable, решения маршрутизации, фаза,
  текущие результаты и временные метки. Изменение объёма, требований или
  зависимостей требует нового плана. Смысловые границы пакета,
  блокирующее/событийное ожидание агентов и проверка фактического diff без
  повторения исследования worker остаются рекомендациями, а не универсальными
  гарантиями принуждения.
- Повторное использование детерминированных проверок проекта включается явно.
  `checks_reusable` — строгое булево поле со значением `false` по умолчанию;
  только явное `true` подтверждает, что каждая команда набора является
  детерминированной локальной проверкой проекта. Reuse доступен через
  `workspace verify --reuse-checks`; `workspace verify --force` и
  `--force-checks` управляемого worker всегда выполняют проверки заново.
  Повторно использовать результат можно только при подтверждённо неизменных
  представленных входных данных и окружении проекта, а также валидных прежних
  успешных свидетельствах. Изменённые, неизвестные, неуспешные, усечённые или
  небезопасные свидетельства и явный force требуют выполнения. Проверки
  готовности, безопасности и изоляции всегда свежие, а приёмка координатора
  никогда не выводится только из повторно использованной проверки worker.
- Известные неисправности среды до обращения к провайдеру запоминаются в
  ограниченной приватной записи. Одинаковые попытки подготовки среды и создания
  рабочей копии блокируются до обращения к провайдеру, пока соответствующие
  условия остаются подтверждённо неизменными. Изменённые условия или `--recheck-environment`
  разрешают свежую диагностику. Эта память не обходит песочницу, доступ,
  допуск или восстановление и не охватывает сбои провайдера, аутентификации
  или обычных тестов проекта.
- Ожидание слота worker использует уведомления ядра с консервативным fallback,
  сохраняя порядок FIFO, сроки и отмену. Завершение процесса будит ожидающих;
  отказ от частого опроса со стороны координатора остаётся инструкцией агенту.
- Явно запланированная доработка проверенного успешного результата
  `needs-rework` может объявить `correction_of {task_id, assignment_id}`. До
  выделения ресурсов runner находит исходные незакрытые workspace и job,
  повторно использует стабильную копию и подготовленные инструменты и начинает
  новую попытку. Координатору не нужно помнить или передавать `--workspace`;
  конфликтующее явное значение отклоняется. Неверные, неоднозначные, устаревшие,
  чужие, финализированные или небезопасные связи отклоняются до выделения.
  Неудачные попытки по-прежнему требуют явного `--resume-after-failure`.
- Сводки `SessionStart` после компакции и `UserPromptSubmit` восстанавливают
  workspace, job, попытку и происхождение доработки из приватного журнала
  независимо от памяти модели. Защита от пропущенной связи при перекрытии
  действует в пределах задачи; смысловые межзадачные доработки требуют явной
  связи. Финализация следует по принятой цепочке доработок между задачами.
  Доставка hooks охватывает распознанные события, которые передаёт runtime, а
  не любые возможные записи.
- Текущее запланированное состояние использует schema 2. Миграция старых
  форматов планового состояния не предоставляется; эти форматы диагностируются,
  но не мигрируются и не считаются совместимыми. Это отдельно от сохранения
  человеческого руководства и пользовательских политики и конфигурации.

Команды обновления и проверки приведены в английском разделе выше. Установка
пакета сама не подключает проект и не выдаёт нативное доверие hooks. Живая
доставка lifecycle hooks требует включённого делегирования и доставки событий
runtime.

Результаты проверки относятся к этому кандидату и не являются гарантией для
каждой машины. Нативное выполнение Claude не заявлялось, а покрытие hooks не
является универсальным.
