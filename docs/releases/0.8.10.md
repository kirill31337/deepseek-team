# DeepSeek Team 0.8.10

## English

Coordinated read-only workers could fail before model launch when the persistent
`workspaces` directory was a symbolic link, while `doctor --offline` reported
successful local checks. This release checks the actual selected storage before
delegation and identifies the failing path and cause.

- Setup checks storage before modifying runtime configuration or reading a key.
  Session/prompt bootstrap checks it before opening a coordination task. Missing
  private directories are created with mode 700; a short local directory/file
  allocation probe is removed afterwards.
- Later tool/stop hooks honor the same storage failure before accessing an old
  task. Direct ledger access also refuses unsafe roots without changing rights
  or following linked ancestors.
- Offline doctor checks storage even with read-only access. It now accepts
  `--state-dir`, reports the checked root, and forwards that selection to live
  synthetic worker checks.
- Workers and workspace commands now share the live `DEEPSEEK_TEAM_STATE_DIR`
  default already used by coordination, routing and lessons. Command-level
  `--state-dir` remains the priority for worker storage only.
- Diagnostics distinguish symbolic links, foreign owners, permissions and
  inaccessible storage. No link is followed to adopt a workspace, existing
  permissions are not changed, and copies or ledgers are not moved or deleted.
  Mandatory Bubblewrap/AppArmor worker isolation is unchanged.
- Both full and compact linked bootstrap templates explain readiness and
  recovery. Human-maintained linked guides remain untouched.

For an ordinary private storage root outside the project, set the environment
before starting the coordinator and run setup:

```bash
pipx install --force https://github.com/kirill31337/deepseek-team/releases/download/v0.8.10/deepseek_team-0.8.10-py3-none-any.whl
export DEEPSEEK_TEAM_STATE_DIR=/absolute/private/deepseek-team-state
deepseek-team setup --runtime codex --no-key   # or claude / both
deepseek-team doctor --runtime codex --offline
```

Keep the existing root and its retained data. Selecting a new shared root does
not migrate old task IDs, workspaces, routing history or lessons; register new
coordination work there. A `--state-dir` command override does not change the
coordinator's ledger location. Use the same worker storage for concurrent jobs.
Package upgrade alone does not run setup or change the storage location.
The command above selects this GitHub release explicitly; a plain `pipx upgrade`
selects the version available from PyPI, which may differ.

## Русский

Координируемое задание read-only могло остановиться до запуска модели, если
постоянный каталог `workspaces` оказался симлинком, хотя `doctor --offline`
сообщал об успешной проверке. Этот выпуск проверяет выбранное хранилище до
делегирования и явно указывает проблемный путь и причину.

- Setup проверяет хранилище до изменения конфигурации координатора и чтения
  ключа. Бутстрап сессии/запроса — до открытия задачи координации. Отсутствующие
  приватные каталоги создаются с правами 700; временная локальная проверка
  создания каталога и файла удаляется после завершения.
- Последующие события инструментов/завершения учитывают тот же отказ до чтения
  старой задачи. Прямой доступ к журналу также отклоняет небезопасный корень,
  не меняя права и не проходя через ссылки в родительских каталогах.
- Офлайн-диагностика проверяет хранилище даже при read-only. `doctor` принимает
  `--state-dir`, показывает выбранный корень и передаёт его синтетическому воркеру
  при live-проверке.
- Worker и команды workspace используют актуальную `DEEPSEEK_TEAM_STATE_DIR`,
  как координация, маршрутизация и уроки. Явный `--state-dir` приоритетнее для
  рабочего хранилища конкретной команды и не переключает журнал координатора.
- Ошибка различает симлинк, чужого владельца, права и недоступное хранилище.
  Пакет не принимает рабочие копии через ссылки, не меняет существующие права,
  не переносит и не удаляет копии и журналы. Обязательная песочница сохраняется.
- Полный и сокращённый linked-бутстрапы объясняют проверку и восстановление.
  Поддерживаемые вручную linked-гиды не перезаписываются.

Выберите обычный приватный каталог вне проекта, задайте переменную до запуска
координатора и выполните команды обновления и setup из примера выше.
Сохраните старый корень и его данные: смена общего пути не переносит старые ID
задач, копии, историю и уроки. В новом корне нужно зарегистрировать новые задания;
одновременно работающие воркеры должны использовать одно рабочее хранилище.
Само обновление пакета не запускает setup и не переключает хранилище.
