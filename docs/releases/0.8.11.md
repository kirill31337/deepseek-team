# DeepSeek Team 0.8.11

## English

Projects can recover from an unusable default worker-storage directory without
exporting environment variables. After updating, the next enabled attached
project bootstrap checks storage and saves a private replacement when safe.
Setup and offline doctor support the same recovery.

- The selected directory is created with mode 700 under the current user's home.
  Its choice is saved privately in `~/.config/deepseek-team/storage/selection.json`
  (or the equivalent under `XDG_CONFIG_HOME`) with mode 600. Every coordinator
  store and command reads the same choice across sessions and upgrades.
- A healthy default stays in use. Explicit `--state-dir` and
  `DEEPSEEK_TEAM_STATE_DIR` keep priority. An invalid explicit or saved selection
  is diagnosed and preserved rather than silently replaced.
- Switching holds the previous root's allocator lock through publication and
  requires no active worker slots or live FIFO tickets. Pending jobs that already
  resolved the old automatic root revalidate it before admission and are rejected
  if the selection changed. No provider request is needed for these checks.
- The old root must be an ordinary owned inspectable directory without linked
  ancestors. If inactivity cannot be proved, recovery stops with a diagnostic.
  Existing copies, links, permissions, ledgers and even stale tickets are kept.
  Old tasks, routing history and lessons are not migrated; new coordination work
  is registered under the replacement root.
- Bootstrap and doctor display the selected root. The mandatory worker OS
  sandbox, project activation and explicit access policy are unchanged.

Upgrade from this GitHub release (PyPI publication is disabled in the repository):

```bash
pipx install --force https://github.com/kirill31337/deepseek-team/releases/download/v0.8.11/deepseek_team-0.8.11-py3-none-any.whl
deepseek-team setup --runtime codex --no-key   # or claude / both
deepseek-team doctor --runtime codex --offline
```

No variable is required. An already attached project with enabled trusted hooks
also performs storage recovery at its next session or prompt after the update.
Package installation itself does not run project setup or grant native hook trust.

## Русский

Если стандартное хранилище воркеров непригодно, проект теперь может выбрать и
запомнить новый приватный каталог без переменных окружения. После обновления
это выполняет следующий бутстрап подключённого включённого проекта. Setup и
офлайн-диагностика используют тот же механизм.

- Новый каталог в домашней директории имеет права 700. Выбор сохраняется в
  `~/.config/deepseek-team/storage/selection.json` с правами 600; учитывается
  `XDG_CONFIG_HOME`. Все команды и хранилища координатора читают один путь,
  который сохраняется между сессиями и обновлениями.
- Исправный стандартный каталог остаётся на месте. Явные `--state-dir` и
  `DEEPSEEK_TEAM_STATE_DIR` приоритетнее. Повреждённый явный или сохранённый
  выбор сообщает об ошибке и не заменяется скрыто.
- Смена пути удерживает блокировку старого распределителя до сохранения выбора.
  Работающие и ожидающие воркеры запрещают переключение. Задание, уже выбравшее
  старый автоматический путь, проверяет его повторно перед допуском и отклоняется
  при изменении выбора. Проверки не обращаются к провайдеру.
- Старый корень должен быть обычным каталогом текущего пользователя, доступным
  для проверки без ссылок в пути. Если отсутствие воркеров нельзя доказать,
  восстановление останавливается с диагностикой. Копии, ссылки, права, журналы
  и даже устаревшие файлы очереди сохраняются. Старые задачи, история и уроки
  не переносятся: новые задания регистрируются в выбранном хранилище.
- Бутстрап и doctor показывают выбранный путь. Песочница, включение проекта и
  явно выбранный доступ остаются прежними.

Команды обновления, setup и проверки приведены выше; переменная не нужна.
Подключённый проект с включёнными доверенными хуками также проверяет и выбирает
хранилище при следующей сессии или запросе после обновления. Установка пакета
сама не запускает setup проекта и не выдаёт доверие хукам координатора.
