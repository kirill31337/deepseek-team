# DeepSeek Team 0.8.7

**English** | [Русский](#русский)

This release repairs instruction propagation for already attached projects. An upgrade
now refreshes the shipped rules automatically instead of requiring a manual `init` in
every project. No delegation, quality or lessons feature changed.

- `SessionStart` and `UserPromptSubmit` in an explicitly attached project check and refresh stale
  existing owned blocks - `AGENTS.md` and `CLAUDE.md` - from the current packaged
  template and that project's effective settings. Unattached projects are never
  created, scanned or registered: the hook creates no file or block where none exists.
- `setup` still installs the user-level hooks for the selected runtime(s) and now also
  refreshes both already-attached instruction files in the repository it runs from. Any
  other attached project picks up the same refresh at its next session or prompt.
- `SessionStart` injects the full current policy for both Codex and Claude Code. When a
  refresh changes a block or fails, the next prompt supplies fresh policy so a stale
  loaded block does not keep steering the session.
- The delegation `off` bypass is unchanged. A stale `off` -> `init` -> `on` snapshot
  recovers at the next bootstrap.
- Ownership checks, byte preservation outside the owned blocks, idempotency and
  transactional refresh are unchanged: only package-owned blocks are rewritten, a
  malformed owned block aborts the refresh, while unrelated files stay untouched, and a failed
  refresh reports visible diagnostics. The package still cannot grant native hook trust,
  so review `/hooks` in the runtime.

The shipped rules are current as of 0.8.6, so this release adds no missing quality or
lessons feature. Upgrading refreshes the shipped rules only: your project-local access,
manual 25/50/75 profile, `effort`, `max_workers` and `off` state are preserved, the
private lessons journal stays local, and no full-access setting or learned rule is
exported. No delegation percentage is shipped or promised, and fresh access stays Auto
and read-only until you opt in to `full-access`.

Upgrade the package, then run `setup` once for each coordinator runtime you installed:

```bash
pipx upgrade deepseek-team
deepseek-team setup --runtime codex --no-key   # or claude / both
```

Start a new session and review `/hooks` if the runtime requires it. Installing or upgrading with pip, pipx or uv
does not run setup automatically. Setup updates hook definitions; native trust is
reviewed separately in the coordinator. Closed projects refresh on their next session. Run `init` only to attach a
project for the first time or to deliberately repair its managed blocks.

## Русский

Этот релиз исправляет распространение инструкций для уже подключённых проектов.
Обновление пакета теперь обновляет поставляемые правила автоматически, а не требует
ручного `init` в каждом проекте. Функции делегирования, качества и уроков не менялись.

- `SessionStart` и `UserPromptSubmit` в явно подключённом проекте проверяют оба
  существующих управляемых блока и обновляют устаревшие — `AGENTS.md` и `CLAUDE.md` — по текущему шаблону
  пакета и действующим настройкам этого проекта. В неподключённых проектах файлы не
  создаются, не сканируются и не регистрируются: хук не создаёт файл или блок там,
  где их нет.
- `setup` по-прежнему устанавливает пользовательские хуки для выбранных координаторов,
  а теперь ещё и обновляет оба уже подключённых файла инструкций в том репозитории,
  откуда он запущен. Остальные подключённые проекты получают то же обновление при
  следующей сессии или запросе.
- `SessionStart` добавляет полную действующую политику и для Codex, и для Claude Code.
  Если обновление изменило блок или завершилось ошибкой, следующий запрос выдаёт
  свежую политику, чтобы устаревшая загруженная версия не продолжала влиять на сессию.
- Обход делегирования через `off` не меняется. Устаревший снимок `off` -> `init` -> `on`
  восстанавливается при следующей загрузке.
- Проверка владения, сохранение байтов вне управляемых блоков, идемпотентность и
  транзакционное обновление не меняются: перезаписываются только блоки, которыми
  владеет пакет, повреждённый управляемый блок прерывает обновление, а посторонние файлы остаются нетронутыми,
  а неудачное обновление выводит заметную диагностику. Пакет по-прежнему не может
  выдать доверие к нативным хукам — проверьте `/hooks` в координаторе.

Поставляемые правила актуальны на 0.8.6, поэтому релиз не добавляет пропущенных
функций качества или уроков. Обновление затрагивает только поставляемые правила:
права доступа проекта, ручной профиль 25/50/75, `effort`, `max_workers` и состояние
`off` сохраняются, приватный журнал уроков остаётся локальным, а настройки `full-access`
и выученные правила никуда не экспортируются. Одинаковая доля делегирования в разных проектах не
обещается, а свежий доступ остаётся Auto и read-only до явного включения `full-access`.

Обновите пакет и выполните `setup` один раз для каждого установленного координатора:

```bash
pipx upgrade deepseek-team
deepseek-team setup --runtime codex --no-key   # либо claude / both
```

Начните новую сессию и при необходимости проверьте `/hooks`. Установка и обновление через pip, pipx или
uv не запускают настройку автоматически. Setup обновляет определения хуков; доверие
к ним подтверждается отдельно в координаторе. Закрытые проекты обновятся при следующей сессии. Запускайте `init` только для первого
подключения проекта или намеренного восстановления управляемых блоков.
