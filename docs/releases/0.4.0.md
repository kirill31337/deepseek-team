# DeepSeek Team 0.4.0

## Highlights

- Added configurable delegation profiles: **25%**, **50%**, and **75%**.
- Added independent `access = auto | read-only | full-access` policy with layered precedence: CLI > project > global > defaults.
- Added reusable, package-owned full-access development copies that can create/edit/delete project files and run local tests/builds without requiring an upfront `--allow-write` file list.
- Preserved the legacy exact-file `--write --allow-write` mode for narrow changes.
- Added managed workspace preparation, explicit recovery after partial failures, and isolation between up to three concurrent workers.
- Added runtime-aware managed full-access checks for Codex and Claude Code.
- Added sparse Bubblewrap isolation for managed development, private networking, and a fixed DeepSeek provider relay that keeps the real provider credential host-side.
- Added reproducible permission verification with pinned Codex CLI 0.154.0 and Claude Code 2.1.273 against an offline provider fixture.
- Hardened managed runtime mounts so npm/Node installations under user prefixes do not expose all of `~/.local`.
- Improved provider-vs-execution failure classification while preserving partial work for inspection.

## Compatibility

Default behavior remains compatible: without new settings, the effective profile is **25% / read-only**. Existing Codex/Claude setup, the `deepseek-team` and legacy `codex-deepseek-team` commands, and the legacy exact-file writer remain supported.

## Verification

The implementation line passed the full Python 3.11/3.12/3.13 test matrix, Ubuntu AppArmor/Bubblewrap smoke checks, and dedicated real-runtime permission verification without using a live DeepSeek API key or paid inference request.

See `docs/VERIFICATION.md` for detailed evidence and deliberate limits.
