# DeepSeek Team 0.8.0

This release adds useful delegation from the first session, a FIFO worker queue, standard pipx/uv/pip distribution preparation and improved first-run setup.

- `setup` now detects installed coordinators by default and checks Git, command availability, the required OS sandbox and local runtime capabilities before reading a credential.
- `setup --with-sandbox` explicitly permits Ubuntu system-package and AppArmor setup. A working sandbox is reused; ordinary setup never runs privileged installation commands.
- `setup --no-key` defers authentication without reading credentials. Noninteractive setup without a key reports an incomplete setup instead of success.
- `setup --configure-only --runtime codex|claude|both` retains configuration-only automation without claiming that workers are ready. Existing integrations remain active; updates do not require reattaching projects.
- Both READMEs include user-level installation, explicit project paths, upgrades and removal. The distribution remains `codex-deepseek-team`; both CLI names are preserved.
- Distribution checks exercise pip, pipx and uv with isolated homes, installed resources and removal. Version-tag releases build and verify artifacts before separate Trusted Publishing jobs.

- Auto now defaults to `admission_policy=immediate`: eligible bounded small/medium tasks need no cold-start history, trial cap, periodic coordinator holdout or recovery stride. `--admission-policy evidence` retains the previous stages. Explicit permissions, saved manual profiles and `off` remain authoritative; fresh Auto access stays read-only. Opt in to `full-access` to delegate implementation.
- Unknown costs do not block eligible immediate assignments or imply savings. Supported bad measured economics still veto. A rejection or three distinct rework cases within the cooldown window pause a family; the new default cooldown is 300 seconds, preserving saved values. One rework remains recorded without a pause. Failed implementation never retries automatically.
- Worker concurrency defaults to eight, configurable from 1 to 64 with `config set --project --max-workers N` (or `--global`) or a one-job `worker --max-workers N`. Busy slots queue launches FIFO while assignments remain worker-owned. `--no-wait` returns capacity code 75; explicit timeout includes queue time, and the default remains unlimited. Queued launches recheck off/access/routing/HEAD before secrets or provider launch.
- Coordinators decompose independent useful slices, review actual diffs and checks, and report accepted work and rework without invented savings or contribution percentages. Final verification and integration remain coordinator-owned.

PyPI availability depends on the owner completing the one-time setup in [PUBLISHING.md](../PUBLISHING.md). Preparing this release does not register or publish the PyPI project. Linux and Python 3.11+ remain required. Worker isolation, default access, credential handling and native hook trust boundaries are unchanged.
