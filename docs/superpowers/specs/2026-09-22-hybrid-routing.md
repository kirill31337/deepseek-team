# Hybrid delegation routing

> Historical record: this document describes an earlier implementation or verification run. Commands, defaults and compatibility claims here are not current instructions. See [README](https://github.com/kirill31337/deepseek-team/blob/main/README.md) and the current routing guide for supported behavior.

## Authorized outcome

Implement the user's complete hybrid delegation system: public reproducible evidence supplies a bounded prior; actual project assignments supply contextual learning; a conservative, explainable policy can select an executor. This is production package functionality, not a model fine-tuning job or a promised benchmark score. The user explicitly requested implementation without another planning round.

## Contracts and invariants

- Linux, Python >=3.11, standard library only. Existing worker isolation, private credentials, saved 25/50/75 profiles and explicit access remain authoritative.
- Fresh default delegation level is Auto; saved manual 25/50/75 retain priority and continue learning. Auto access remains read-only unless explicitly granted.
- Modes: off, shadow, advisory, auto (default). Existing explicit executor plans retain their behavior; `executor: auto` requests automatic selection. Only auto mode may resolve an automatic executor; an abstention retains the coordinator with a persisted, validated routing reason.
- Never run paid experiments, send project material, fetch remote sources, or widen permissions from a hook. Source refresh and experimentation are explicit commands. No training on raw prompts, source, model transcripts or secrets.
- A validated feature card is captured before execution. Model, effort, runtime and context version identify the execution conditions. Protected coordinator kinds always stay coordinator-owned. Unknown/high risk and inadequate verification cannot become an automatic worker recommendation.
- External evidence is an explicitly imported bounded JSON snapshot with HTTPS provenance, SHA-256 integrity, timestamps, exact model/run identity and task outcomes. Support native evidence-v1 and SWE-bench resolved/unresolved reports; unevaluated/error instances are not model failures. No invented bundled scores, auto-trust of arbitrary URLs, or interpretation of aggregate leaderboard percentages as local probabilities.
- Private, project-scoped SQLite storage lives outside Git. Strict schema, private directories/files, symlink/hardlink rejection, transactions, bounded payloads, idempotent identities and versioned schema. SQLite schema version 2 adds the evidence index; budget and recovery tables are verified as closed schemas. Observation outcomes cannot silently change under the same ID. Multiple attempts at one case are not independent evidence.
- Fractional Beta updating starts at Beta(1,1). Known kind, domain and operation are exact task-family anchors; unknown anchors do not transfer evidence. Context similarity, freshness and provenance reliability weight evidence only within that family. External aggregate and per-source-family caps prevent imported volume from overwhelming local experience. Exact runtime/model/effort/context identity isolates execution drift. Credible intervals are calculated numerically. Forecasts are conditional on recorded outcomes, not formal correctness guarantees.
- Quality outcome is final acceptance without rework; rework/rejection is failure; infrastructure/cancellation/unknown remain unlabelled. The earliest meaningful quality failure for a case dominates earlier or later acceptance. Corrections are immutable chronological events: evaluation preserves the original forecast and learns a correction only when observed. Latest measured total cost is tracked separately.
- Conservative recovery prevents Auto delegation from collapsing permanently while evidence is uncertain. It applies only when both profile and routing mode are Auto, to ordinary fully classified, clear, low-risk, small, locally coupled tasks with known localization/domain/operation/context, `tests` or `reproducer`, declared checks, permitted access and the supported worker model. The default rate is 0.1: select the first eligible binding, then at most one per 10 distinct eligible opportunities project-wide. Allow one pending/running ticket, a one-hour pending TTL, and a one-hour quality-failure cooldown for the same task family plus execution identity. Running work has no scheduler timeout and must be inspected/dispositioned; only unused pending tickets can be released. Recovery never overrides explicit executors, manual profiles, access, protected work, disabled workers, or budget/provider availability, and is not a paid benchmark retry.
- Route using a conservative quality bound, minimum local support and total measured cost (worker plus review/rework) against comparable coordinator observations. Abstain on insufficient evidence; never fabricate the unchosen executor's outcome or subscription dollar cost.
- Experiment budget reservations are atomic, persistent and idempotent with per-run and monthly caps. Reservations govern authorized estimated experiment spending, not provider billing; settlement records actual spending and an overrun blocks further reservations. Never claim a hard provider-dollar cap. No automatic worker retries.
- Chronological evaluation scores each case before learning its outcome, groups repeated cases, applies corrections only at their timestamps, and reports Brier/log loss/calibration/coverage and observed policy outcomes without asserting counterfactual savings. New families and execution contexts start with uncertainty.

## Component ownership and interfaces

`routing_models.py` (coordinator): strict feature/config/observation validation and RoutingError(message, code=64).

Feature dictionary fields: kind, domain, operation, localization, coupling, verification, clarity, risk, scope_size, runtime, model, effort, context_version. Categoricals are defined in routing_models.FEATURE_VALUES; defaults in FEATURE_DEFAULTS. All inference receives normalized dictionaries. `validate_features(dict) -> dict`; `validate_config(dict, base=None) -> dict`; `validate_observation(dict, now=None) -> dict`. Observation fields: id, case_id, origin(local|external), source_id, source_family, features, action(worker|coordinator), outcome(accepted|rework|rejected|infrastructure|cancelled|unknown), observed_at(epoch seconds), cost_usd(optional total including review/rework), duration_seconds(optional), reliability(0..1), decision_id(optional). Source payloads never store code or prompts.

`routing_estimator.py` (native agent): pure `estimate(features, observations, config, *, now=None) -> dict` returning mean/lower/upper/alpha/beta/local_effective/external_effective/matched_local/matched_external/evidence_ids. `recommend(features, observations, config, *, access='read-only', enabled=True, now=None) -> dict` returning action(worker|coordinator|abstain), reason_codes, posterior, economics. `evaluate(observations, config, *, now=None) -> dict` chronological grouped evaluation. Config keys/defaults defined in routing_models.DEFAULT_CONFIG. No file/network I/O.

`routing_sources.py` (native agent): `parse_snapshot(data: bytes, *, source_id: str, source_url: str, expected_sha256: str, reliability: float=0.5, now=None) -> dict` returns metadata {id,url,sha256,imported_at,format,source_family} and observations. Native JSON: schema_version=1, format='deepseek-team-evidence', source_family, observations; native observations supply all fields except origin/source_id/reliability which import fixes. SWE-bench JSON: schema_version=1, format='swe-bench', source_family, run_id, observed_at, features, evaluated_ids, resolved_ids, optional instance_features keyed by instance ID, optional costs_usd keyed by ID. Require resolved subset of evaluated, duplicate rejection; hash case_id from family+instance to deduplicate repeated runs. `fetch_snapshot(url, *, max_bytes=8*1024*1024, timeout=20) -> bytes`: HTTPS only, no URL credentials/query/fragment, explicit network CLI only; block local/private/link-local/multicast/reserved destinations, redirects, proxies and oversized streams. Tests use controlled mocks, never live network.

`routing_store.py`, `routing.py`, `routing_budget.py` and `routing_recovery.py` (coordinator plus reviewed worker contribution): durable state and public service. `RoutingService(root: Path)` exposes config/configure/status, source import, observation/prediction/decision/evaluation, budget reserve/settle/release, recovery status/start/release, bounded `export()` and streaming `export_to(stream)`. The CLI does not touch storage internals. The export keeps the existing schema-version-1 JSON shape; the CLI streams it and uses a private fsynced atomic replacement for file output rather than holding the full state in memory.

`routing_cli.py` (native agent): `main(argv)` receives ['routing', ...]. Commands: status/config [--json], configure --mode ... and numeric/bool settings, import FILE --source-id --source-url --sha256 [--reliability], fetch URL --source-id --sha256 [--reliability], recommend [--file FILE otherwise stdin] [--access read-only|full-access], observe [--file otherwise stdin], evaluate, streaming export [--output FILE otherwise stdout], budget reserve/settle/release, and recovery status/release. All accept --path project and structured JSON output. Source fetch must be explicit and pinned. Bound JSON reads, readable errors, no tracebacks/secrets. Use only service and models APIs. CLI examples/docs are in docs/ROUTING.md (EN) and docs/ROUTING.ru.md (RU).

Coordinator integrates CLI dispatch/help, `executor:auto` planning, immutable decision/feature capture, actual execution identity, failure classification and coordinator/worker disposition feedback. A durable ledger outbox is written before SQLite observation recording and replayed idempotently after interruption. Replanning cannot remove or redefine completed feedback history.

## Verification and limitations

Unit/property tests cover posterior quantiles, source caps, task-family isolation, mismatches, abstention, drift, corrections, duplicated cases, chronological leakage, recovery guards/rate/concurrency/cooldown, hostile source and storage input, SQLite concurrency/idempotency, streaming export, and coordinator auto-plan/outbox integration. Final full-suite, package build/install smoke and integrated diff review remain pending.

## Execution record

Three actual managed DeepSeek workers ran inside the required sandbox for the budget ledger, Auto settings, and recovery scheduler. Their changes were imported and reviewed by the coordinator. Ubuntu AppArmor remained enabled, the provider key remained private and outside Git/logs, and four package hooks were trusted through native Codex `hooks/list` plus `config/batchWrite` API calls. The two baseline native Codex integration failures were diagnosed as fixture defects and their fixes were kept independent of routing behavior.

## Final verification

Implemented and installed 0.7.0. The original checkout passed 472 tests (three Claude CLI availability skips), wheel/sdist build, clean installed CLI smoke, and offline doctor. Lifecycle review additionally verified transactional plan/start batches, recoverable JSON/SQLite crash boundaries, explicit inspected abandonment of stopped workers, and current access checks with preserved explicit CLI precedence. Four package hooks remain trusted through the native API; AppArmor restrictions remain enabled.
