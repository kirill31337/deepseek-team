# Early delegation and coordinator authority

The user approved applying the recommendations from the 0.8.4 low-delegation
analysis. Success means useful work reaches Auto before the coordinator solves
it, ordinary tasks cannot silently bypass Auto, and protected responsibility does
not grant blanket implementation authority. No target contribution percentage
is enforced or measured.

## Boundaries

- Preserve existing uncommitted preparation/recovery improvements.
- Preserve explicit access, manual profiles, disabled delegation, native-agent
  exceptions, required worker OS isolation, and retained worker copies.
- Do not relax risk, verification, environment, cost, or cooldown admission.
- Do not automatically install, publish, commit, grant access, or migrate private
  state. Test the reusable package and refresh this project's generated guidance.
- Genuine small single-output tasks retain their concrete-scope exemption.

## Distribution

Substantial Auto plans must request `executor: "auto"` for ordinary read and
write kinds. Both explicit `coordinator` and explicit `worker` bypasses receive
an actionable error. Protected coordinator responsibilities and attested native
exceptions retain explicit executors. Preserve valid immutable routing decisions
for already-started work, including historical shadow/advisory/off router decisions,
and never silently replace a live assignment. New ordinary Auto work requires router
mode Auto; incompatible modes produce an explicit configuration diagnostic.

Plan output and status explain requested/resolved executor, routing reasons, and
safe next steps. Unknown features remain unknown. Suggestions distinguish bounded
diagnostics, decomposition, missing checks, explicit access opt-in, and temporary
quality/economic restrictions. No hidden automatic job creation or retries.

## Early investigation

For enabled attached coordinator sessions, a recognized source inspection on an
unplanned task records `source_inspection` and returns a planning reminder. Further
recognized inspection requires classification and a concrete distribution. A
duplicate nonempty tool-use identity must not consume orientation twice.

Read/Grep/Glob and common shell inspection commands are recognized for the tool
spellings delivered by Codex and Claude. Status/bootstrap commands, instruction
reads, waits, worker children, and conversational turns remain exempt. Opaque
scripts are not claimed to be intercepted. Inspection is work, so Stop may no
longer close that task as an untouched draft. Small source-informed answers can
register a small concrete plan; no fabricated worker is required.

## Protected mutation authority

Existing `scope` remains a context/read boundary. It alone does not permit source
writes for architecture, security, integration, verification, or other protected
responsibilities.

Optional `decision_artifacts` lists exact relative `.md`, `.rst`, or `.txt`
documentation files within the registered scope. Directories, globs, traversal
outside the project and source/config files confer no authority.

Integration writes additionally use:

```json
{
  "id": "integrate",
  "kind": "integration",
  "executor": "coordinator",
  "scope": ["src/example.py", "tests/test_example.py"],
  "integration_of": ["implementation"],
  "write_scope": ["src/example.py", "tests/test_example.py"]
}
```

The fields supplement the existing required plan fields. Each written file must
be backed by a referenced terminal worker's actual changed files, or by a current
accepted coordinator write deliverable with a recorded concrete mutation.
Read-only reviews, self references, unknown references and pending assignments
provide no source authority. A file authorization never permits deleting its
parent directory. Existing cross-task pending-worker and canonical path checks
remain mandatory. Discovered implementation requires its own routed deliverable.

All three new metadata fields are part of immutable deliverable identity after
execution/acceptance. Validate their shape on registration and at runtime.

## Guidance and onboarding

Explain early bounded diagnostics, independent slices, one batched plan, and
launching workers before duplicating their scope. Clarify the protected write
contract with an implementation-plus-integration example.

Setup explicitly explains fresh Auto read-only access and prints the full-access
opt-in command without executing it. Preserve explicit settings. Explain refresh
of attached guidance after upgrades. Final contribution reporting remains a
subjective estimate of accepted work, not a measured execution rate or a router
feedback signal.

## Verification

Regressions cover explicit Auto bypasses, permitted exceptions, truthful routing
diagnostics, early investigation and status/worker exemptions, namespaced tools,
duplicate events, broad protected scopes, actual-output integration, malformed
metadata, aliases, directory deletion and pending-worker precedence. Existing
Codex/Claude fixture coverage and the complete unittest suite must pass. No
universal hook coverage claim or real-provider inference is required by tests.

Coordinator review additionally checks stale accepted results, terminal rejected
or failed output, exact-file rename/delete behavior, unscoped recognized mutations,
documentation symbolic or hard-link aliases into source files, and mixed bootstrap-plus-source
shell commands. Installed hook matchers must deliver the supported read events;
testing only the handler directly is insufficient coverage.
