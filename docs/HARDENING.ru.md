# Изоляция и безопасность

[English](https://github.com/kirill31337/deepseek-team/blob/main/docs/HARDENING.md) | **Русский**

DeepSeek Team проверяет действия координатора и отдельно ограничивает доступ воркеров к системе. За архитектуру, безопасность, итоговую проверку, перенос изменений в основной проект, работу с секретами и цифровыми подписями, коммиты, публикацию и действия в боевой среде отвечает координатор. Воркеры используют модель `deepseek-flash` и выполняют только порученные им задания: они не запускают других агентов и не публикуют результаты.

## Как контролируется работа координатора

В проектах, подключённых к DeepSeek Team, Codex и Claude Code сохраняют ход работы в журнале координации. Хуки `SessionStart` и `UserPromptSubmit` восстанавливают состояние задачи. Перед изменением файлов `PreToolUse` проверяет, предусмотрено ли действие планом, входит ли файл в согласованный объём работы и не поручено ли это изменение уже работающему воркеру. Эти проверки распространяются на поддерживаемые инструменты и команды.

Хук `Stop` просит продолжить работу, если остались незавершённые задания, непроверенные результаты воркеров или незафиксированные результаты координатора и его встроенных субагентов. При повторном вызове `Stop` незавершённая работа остаётся в журнале, но хук перестаёт требовать продолжения, чтобы не возник бесконечный цикл. Ответ без запланированной или выполненной работы можно завершить без плана распределения; сообщать о завершённой реализации в таком ответе не следует.

Для каждой части работы, порученной координатору или его встроенному субагенту, нужно явно записать итог: результат принят либо работа отменена. Если система затем зафиксирует новое изменение в тех же файлах, потребуется повторная приёмка. Одной записи об оценке качества недостаточно для завершения работы.

Хуки не могут перехватить любую произвольную программу или автоматически охватить новые инструменты среды. В режиме планирования Claude файлы планов находятся в каталоге, указанном в его настройках. Действия встроенных субагентов Claude не проходят через проверки, предназначенные для координатора. Доверием к хукам управляет сам Codex: проверьте их через `/hooks`. DeepSeek Team не может подтвердить доверие за пользователя или определить его по косвенным признакам. Настройки Codex и Claude Code позволяют отключать хуки; команда `hooks status` не подтверждает, какие хуки загрузила уже работающая сессия.

Встроенные субагенты координатора используют его модель, права и песочницу. В плане нужно обосновать, зачем привлекать такого субагента. При ручных профилях 50/75 его работа не заменяет задания на написание кода, которые по правилам профиля нужно передать DeepSeek.

## Обязательная песочница Linux

До обращения к API-ключу для каждого воркера проверяется работоспособность песочницы Linux. Ограничения AppArmor на пользовательские пространства имён остаются включёнными. В Ubuntu пакет может установить отдельный профиль `deepseek-team-bwrap`: он разрешает создание пространств имён, а Bubblewrap ограничивает доступ к файловой системе и процессам.

В режиме только чтения Codex использует собственную песочницу и изолированный запуск через Bubblewrap. Claude в этом режиме целиком запускается внутри пространства имён Bubblewrap и сохраняет возможность прямого сетевого соединения с провайдером модели. Права инструментов Codex и Claude Code разрешают только операции чтения.

В режиме полного доступа и Codex, и Claude Code работают в отдельных копиях проекта внутри песочницы Bubblewrap. Внутри неё доступны только копия конкретного воркера, каталоги, необходимые для запуска среды, временный домашний каталог и служебные данные этого запуска. Служебные файлы Git доступны только для чтения. Копии других воркеров и исходный рабочий каталог пользователя скрыты.

Сеть также изолирована. Для обращения к API модели используется специальный посредник с заранее заданным адресом провайдера; соединение проходит через Unix-сокет и локальный сетевой мост, создаваемые для каждого запуска. API-ключ остаётся на основной машине. Использовать это соединение как прокси для произвольного доступа в интернет нельзя.

Полный доступ позволяет вносить изменения в копию проекта, выделенную воркеру. SDK, базы данных, сервисы и секреты основной машины при этом не становятся ему доступны. Недостающие зависимости заранее подготавливает координатор. Наличие указанных в задании зависимостей проверяется внутри песочницы до обращения к API-ключу. Указанные в задании тесты выполняются там же после работы воркера. Подмена зависимостей заглушками не считается полноценной проверкой проекта.

## Очередь заданий, права и восстановление после сбоев

После установки режим Auto разрешает воркерам только чтение. Явно заданные права, ручные профили и отключение через `off` имеют приоритет над автоматическим выбором. Для написания кода нужно отдельно разрешить полный доступ. Задачи с понятным объёмом, которые отвечают условиям автоматического делегирования, можно передавать сразу. Результаты проверки качества записываются без приукрашивания. Отказ от делегирования из-за затрат должен опираться на измеренные данные; если стоимость неизвестна, заявлять об экономии нельзя.

Назначенная задача может ждать запуска в очереди. По умолчанию одновременно работают до восьми воркеров; остальные задания запускаются в порядке поступления (FIFO). Если все воркеры заняты, задание остаётся в очереди и не переходит к координатору. Перед обращением к ключу и запуском задания повторно проверяются состояние `on`/`off`, права доступа, разрешение на делегирование и текущий HEAD проекта. Блокировка рабочей копии не позволяет двум процессам одновременно менять её файлы. По умолчанию время ожидания и общая длительность задания не ограничены. Если тайм-аут задан явно, в него входит и ожидание в очереди.

Если задание на написание кода завершилось с ошибкой, рабочая копия и изменения сохраняются. Перед повторным запуском их нужно просмотреть: автоматически такое задание не перезапускается. Если связь с управляющим процессом потеряна, отменять задание можно только после подтверждения, что процесс воркера остановлен, и получения исключительной блокировки его рабочей копии. Долгое ожидание или отсутствие новых сообщений сами по себе не означают, что воркер завершился с ошибкой.

## Где хранятся настройки, результаты и ключи

Журнал координации и данные для выбора исполнителя хранятся вне Git. Для выбора исполнителя используется база `routing-v3.sqlite3` в формате 3. Если у этой базы неподдерживаемая версия, работа с ней прекращается. Базы старых форматов не читаются, не преобразуются и остаются нетронутыми. При проверке завершения задач учитываются актуальные записи о результатах.

Ключ DeepSeek хранится в `~/.config/codex-deepseek/api-key`. Каталог доступен только владельцу, права файла — 600. Вместо файла можно передать ключ через переменную `DEEPSEEK_API_KEY`. Ключи, локальные настройки и полные журналы работы модели не должны попадать в Git. При установке и удалении пакета нужно сохранять выбранную модель координатора, его авторизацию и настройки, не относящиеся к DeepSeek Team.

Эти ограничения не обеспечивают полную защиту от вредоносного кода в репозитории или исполняемых файлах координатора. Кроме того, в доступных модели файлах могут находиться секреты. Если нужна более строгая изоляция, используйте отдельного пользователя ОС, контейнер или виртуальную машину. Тесты без сети проверяют работу самого пакета; для проверки реального обращения к модели нужен отдельно разрешённый запуск с подключением к провайдеру.
