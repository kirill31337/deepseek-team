# DeepSeek Team

[English](https://github.com/kirill31337/deepseek-team/blob/main/README.md) | **Русский**

**Субагенты DeepSeek Flash в вашей сессии Codex или Claude Code.**

Координатор планирует работу, поручает воркерам отдельные задачи, проверяет результат и переносит принятые изменения в проект. Воркеры работают в изолированной среде.

```bash
pipx install deepseek-team
```

Для установки нужны Linux, Python 3.11+ и [pipx](https://pipx.pypa.io/latest/how-to/install-pipx.html). После установки [сохраните API-ключ, настройте хуки и подключите проект](#подготовка-и-подключение-проекта).

*Схема работы с включённым `full-access`.*

Это руководство для версии **0.8.1** пакета `deepseek-team`.

Воркеры работают с моделью `deepseek-flash`. Для них нужен отдельный **ключ DeepSeek API**. По умолчанию координатор выбирает глубину рассуждений (`low`, `medium` или `high`) для каждого задания. При желании можно сохранить один уровень для всех новых заданий.

Сразу после установки воркерам разрешено **только чтение**: они могут изучать проект и сообщать о результатах. Чтобы поручать им изменения кода, явно включите `full-access`. В этом режиме каждый воркер работает в отдельной изолированной копии проекта.

## Требования

- Linux. Поддержка Windows и macOS не заявлена.
- Python 3.11 или новее.
- Git.
- Codex CLI и/или Claude Code CLI. Установите и настройте их обычным способом; команды должны быть доступны через `PATH`.
- Bubblewrap. Песочница обязательна, отключить её нельзя. В Ubuntu команда `setup --with-sandbox` при первоначальной настройке может установить пакет и профиль AppArmor.

Версия 0.8.1 опубликована в [PyPI](https://pypi.org/project/deepseek-team/), поэтому установка выполняется по имени пакета.

## Возможности

- **Автоматическое делегирование.** Auto по умолчанию передаёт воркерам подходящие задачи и учитывает результаты проверки при следующих назначениях. Накапливать историю до первого задания не нужно.
- **Ручные профили.** Профили 25/50/75 позволяют задать желаемую долю работы для DeepSeek.
- **Настройка прав.** Доступ `read-only` или `full-access` выбирается независимо от профиля делегирования.
- **Изолированные копии.** Для каждого задания с правом записи создаётся отдельная копия проекта.
- **Очередь заданий.** По умолчанию одновременно работают до 8 воркеров; лимит можно изменить в пределах от 1 до 64. Остальные задания ждут в порядке поступления — FIFO.
- **Общий ключ.** Codex и Claude Code используют один сохранённый ключ DeepSeek, доступный только вашему пользователю.
- **Один переключатель.** Команды `on` и `off` включают и выключают делегирование в проекте сразу для обоих координаторов.

## Установка и первый запуск

Рекомендуемый способ установки — через `pipx`, по имени пакета из PyPI:

```bash
# Ubuntu: pipx ставится один раз
sudo apt-get install pipx
pipx ensurepath          # затем откройте новый терминал
pipx install deepseek-team
```

Можно также установить пакет через `uv` или через `pip` в виртуальном окружении:

```bash
# uv
uv tool install deepseek-team

# venv + pip (только внутри виртуального окружения)
python3 -m venv ~/venvs/deepseek-team
. ~/venvs/deepseek-team/bin/activate
python -m pip install deepseek-team
```

Установка из локальной копии репозитория:

```bash
git clone https://github.com/kirill31337/deepseek-team.git
cd deepseek-team
pipx install .
```

Не используйте `sudo pip` и не устанавливайте пакет в системное окружение Python.

### Подготовка и подключение проекта

Сначала настройте DeepSeek Team для своего пользователя, затем подключите нужный проект. Это достаточно сделать один раз:

```bash
deepseek-team setup --runtime codex --no-key
deepseek-team auth set
cd /path/to/project
deepseek-team init --coordinator codex .
deepseek-team config set --project --access full-access   # необязательно
deepseek-team doctor --runtime codex --offline
```

Что делает каждый шаг:

- `setup --no-key` проверяет Git, доступность команд и песочницу. Ключ эта команда не читает и не запрашивает.
- `auth set` запрашивает ключ DeepSeek без отображения ввода и сохраняет его с доступом только для вашего пользователя. Без отдельного ключа DeepSeek воркеры не смогут обращаться к модели.
- `init --coordinator codex .` подключает текущий каталог как проект.
- `config set --project --access full-access` — **необязательный** шаг. Выполните его, если хотите разрешить воркерам менять код и запускать тесты в изолированных копиях. При первоначальной настройке Auto без этой команды действует `read-only`.
- `doctor --runtime codex --offline` выполняет локальные проверки без сети и платных запросов.

В Ubuntu для первоначальной настройки может понадобиться `deepseek-team setup --runtime codex --with-sandbox --no-key`. Параметр `--with-sandbox` разрешает установить пакет песочницы и именованный профиль AppArmor. Без него `setup` не вызывает `sudo`, а лишь сообщает о недостающих компонентах. В других дистрибутивах Linux заранее установите необходимые системные компоненты, в том числе Bubblewrap.

Для Claude Code замените `codex` на `claude` в параметрах `--runtime` и `--coordinator`. Если нужны оба координатора, укажите `both`.

Хуки — это обработчики событий сессии, через которые DeepSeek Team подключается к координатору. В Codex откройте `/hooks`, проверьте установленный хук и подтвердите доверие к нему. В Claude Code начните новую сессию и проверьте `/hooks`. Пакет не может подтвердить доверие к хукам за вас.

## Делегирование и текущие настройки

По умолчанию используется профиль **Auto** с `effort=auto`. Auto может передавать подходящие задачи уже в первой сессии: отсутствие истории само по себе не препятствует делегированию. Для этого задача должна быть небольшой или средней, с низким или средним риском. Требования должны быть ясны, место изменений — известно хотя бы частично, а связи с остальным кодом — ограничены отдельным участком или компонентом.

Способ проверки результата тоже нужно определить заранее. Для реализации нужны доступ `full-access` и проверка, которую можно запустить: тесты, сборка или воспроизведение ошибки. Для ревью, исследования и документации достаточно чётких критериев, по которым координатор проверит результат вручную.

Глубину рассуждений воркера задаёт параметр `effort`: `low` подходит для простых и механических задач, `medium` — для обычной работы, `high` — для сложной отладки, анализа нескольких связанных файлов и тщательного независимого ревью. При `effort=auto` координатор выбирает уровень для каждого задания.

Все подходящие независимые задачи можно зарегистрировать заранее. Настройка `max_workers` ограничивает число одновременно работающих воркеров, а не число назначенных заданий. Если свободных мест нет, новые запуски ждут в очереди FIFO. По умолчанию одновременно работают до 8 воркеров; допустимый диапазон — от 1 до 64. Общего ограничения по времени нет. Если задать таймаут явно, в него войдёт и время ожидания в очереди.

Если стоимость неизвестна, это не мешает передать подходящую задачу воркеру. Если же измеренные затраты показывают, что делегирование невыгодно, задача остаётся у координатора.

Доработку результата фиксируют в истории, но один такой случай не вызывает паузы. Если результат отклонён или за период наблюдения доработка потребовалась в трёх разных случаях, передача похожих задач временно приостанавливается — по умолчанию на 300 секунд. После неудачной реализации повторного запуска без явной команды не будет.

### Права доступа

- `read-only` — доступ по умолчанию после установки с профилем Auto. Воркер изучает проект и сообщает о результатах, но ничего не записывает.
- `full-access` — доступ для разработки **в отдельной изолированной копии проекта**. Его включают явно в настройках доступа либо выбором ручного профиля 50/75 при `access=auto`. Воркер меняет только свою копию; координатор проверяет изменения и переносит принятые в основной проект. Доступ ко всем ресурсам хоста этот режим не даёт.

### Ключевые параметры

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| Профиль делегирования | Auto | Выбор исполнителя с учётом задачи и прошлых результатов |
| Права доступа | read-only | `full-access` — только по явному выбору |
| Модель воркеров | `deepseek-flash` | Всегда, без выбора |
| `effort` | `auto` | Координатор выбирает `low`/`medium`/`high` |
| Параллелизм | 8 (от 1 до 64) | Лишние задачи ждут в очереди FIFO |
| Общий таймаут | без ограничения | Явный таймаут включает время в очереди |

Вместо Auto можно выбрать ручной профиль **25/50/75**: он задаёт желаемое распределение работы между координатором и DeepSeek. Эти значения не являются квотами на токены, время или строки кода и не показывают фактический вклад. Ранее сохранённый ручной профиль имеет приоритет над Auto.

При `access=auto` профиль 25 даёт доступ `read-only`, а профили 50/75 — `full-access`. Явно сохранённый `read-only` всегда имеет приоритет. Подробнее — в [руководстве по выбору исполнителя](https://github.com/kirill31337/deepseek-team/blob/main/docs/ROUTING.ru.md).

## Пример задания координатору

В сессии координатора опишите задачу обычными словами и попросите передать её независимые части воркерам:

> Поручи воркерам DeepSeek независимые части этой задачи и тесты к ним. Затем сам проверь результат и перенеси принятые изменения в основной проект.

Координатор определит объём задачи, разделит её на независимые части, запустит воркеров и проверит их результаты.

В пакет входят инструкции по итоговому отчёту для Codex и Claude Code. Когда DeepSeek Team включён, координатор в конце работы кратко перечисляет, что сделал лично, какие результаты DeepSeek принял и что потребовало доработки, было отклонено или завершилось с ошибкой. Отчёт охватывает всю задачу, в том числе работу из предыдущих сообщений. Запланированную, ещё выполняемую, неудачную или отклонённую работу нельзя выдавать за завершённую.

Вклад собственных субагентов координатора указывается отдельно: его нельзя приписывать ни лично координатору, ни DeepSeek. Если делегирования не было, это нужно прямо сказать.

После списка координатор приводит приблизительное соотношение своего вклада и вклада DeepSeek в **принятую работу**: два целых процента с суммой 100 и пометкой **«субъективная оценка, не измерение»**. Оценка учитывает объём и сложность принятой работы, проверку и доработки. Её нельзя вычислять по числу вызовов, задач, файлов, строк, токенов, затраченному времени или пунктам отчёта, брать из настроенного профиля Auto/25/50/75 либо представлять как измерение производительности или экономии денег, времени и токенов.

Если принятых результатов DeepSeek нет, указывается 100/0, а неудачные и отклонённые попытки всё равно упоминаются. Если даже для приблизительной оценки недостаточно оснований, нужно сообщить, что она недоступна. Если вклад собственных субагентов включён в долю координатора, это оговаривается явно. Такое соотношение нужно только для отчёта: оно не записывается в телеметрию и не меняет формат журнала или параметры программы.

Отчёт не требуется, когда делегирование выключено (`off`), ответ содержит только статус или работа не выполнялась. При обновлении пакета обновляются инструкции для хуков. Чтобы обновить инструкции в уже подключённом проекте, выполните `deepseek-team init --coordinator both /path/to/project`; для одного координатора укажите `codex` или `claude`.

## Полезные команды

Диагностика:

```bash
deepseek-team doctor --runtime codex --offline   # локальные проверки, без сети
deepseek-team hooks status --runtime codex
deepseek-team sandbox status
deepseek-team auth status                        # только наличие ключа
```

Настройки и включение:

```bash
deepseek-team config show --effective            # действующие настройки и их источник
deepseek-team config set --project --max-workers 8
deepseek-team on                                 # включить новые задания в проекте
deepseek-team off                                # отключить новые задания
deepseek-team status                             # текущее состояние
```

Команды `on`, `off` и `status` можно запускать из каталога проекта или с указанием пути. Состояние сохраняется в настройках вашего пользователя и не попадает в Git. Ключи и файлы инструкций эти команды не меняют.

## Изоляция

Все воркеры работают в обязательной песочнице Linux. Задания с правом записи выполняются в отдельных копиях проекта с ограниченным доступом к файловой системе и сети. За архитектуру, решения по безопасности, итоговую проверку, интеграцию и публикацию отвечает координатор. Воркерам запрещено создавать коммиты, выполнять push, публиковать и развёртывать изменения, обращаться к боевым сервисам и запускать других агентов.

Для режимов чтения и разработки действуют разные границы изоляции. Правила доступа к файлам, ключам и сети описаны в [руководстве по изоляции](https://github.com/kirill31337/deepseek-team/blob/main/docs/HARDENING.ru.md).

## Обновление и удаление

Обновление выполняется через тот же менеджер пакетов:

```bash
pipx upgrade deepseek-team
deepseek-team setup --runtime codex --no-key
cd /path/to/project
deepseek-team init --coordinator codex .
deepseek-team doctor --runtime codex --offline
```

Повторите `init` в каждом подключённом проекте: команда обновит ту часть инструкций, которую добавляет DeepSeek Team. Ваш текст и сохранённые настройки останутся на месте.

Для установки через uv используйте `uv tool upgrade deepseek-team`; для venv — `python -m pip install --upgrade deepseek-team` из этого окружения. Не устанавливайте пакет одновременно несколькими способами. Если он установлен через pipx из локального клона, обновите клон и выполните в нём `pipx install --force .`.

Если нужно удалить и сохранённый ключ DeepSeek, выполните `deepseek-team auth remove` до удаления пакета.

Удаление:

```bash
deepseek-team detach --coordinator codex /path/to/project   # для подключённых проектов
deepseek-team reset --runtime codex                          # удаляет интеграцию пакета
pipx uninstall deepseek-team
```

Сначала выполните `detach` для подключённых проектов, затем `reset`, чтобы удалить интеграцию DeepSeek Team с координатором, и только после этого удаляйте пакет. Команда `reset` сохраняет ваши основные настройки, выбранную модель координатора и ключ DeepSeek.

Для установки через uv используйте `uv tool uninstall deepseek-team`; для venv — `python -m pip uninstall deepseek-team` из этого окружения. В командах для Claude Code замените `codex` на `claude`; для обоих координаторов укажите `both`.
